# PGSM frame in space_mango — design (2026-10-08)

Status: design approved in conversation with N. Aunai, 2026-10-08; this spec awaits review.

## 1. Goal

Let users get MANGO data in the PGSM ("pseudo-GSM") frame of Michotte de Welle (2024 PhD
thesis, §2.7.3–2.7.4, eqs 2.13–2.20, printed pp. 68–72). PGSM pools measurements taken
under many IMF orientations (magnetosheath) or dipole tilts (magnetosphere) by using
symmetries. The result looks like the GSM map you would get for one target IMF orientation
or tilt range, with much better spatial coverage.

- Magnetosheath: PGSM = the served SWI data rotated about X to a target IMF clock angle
  (eqs 2.19–2.20), after selection by IMF cone angle.
- Magnetosphere: PGSM = GSM plus the dipole-tilt symmetry ψ → −ψ (eqs 2.14–2.16).
  SWI means nothing there, and MANGO does not organize magnetosphere data by IMF.
- Solar wind: no PGSM.

The first consumer besides end users is mango_explorer, which builds its static atlas
offline in Python with `space_mango` and wants a pip-installable transform.

## 2. Sources and verified facts

- Thesis PDF: https://theses.hal.science/tel-04661957v1 (PDF pp. 79–83).
- Upstream notebook: `kaa:/home/michotte/These/Datasets/Preprocessing/Changement_coord/MSH_GSM_to_SWI.ipynb`
  (read-only copy studied 2026-10-08), and `spok.coordinates.swi_base`.
- Served SWI columns, checked against the notebook and on 17 samples (132k rows, all
  spacecraft, 2003–2019):
  - SWI basis: X = −V_sw/|V_sw| (served `V*_sw`, no 29.8 km/s correction);
    Z = X × (s·B_imf)/|…|, Y = Z × X, with s = sgn(Bx_imf) (fallbacks sgn(By_imf), then
    sgn(Bz_imf), when Bx_imf = 0).
  - `B*_swi` = s·R·B (exact). So in SWI the IMF always has Bx > 0 and lies along +Y_SWI.
  - `V*_swi` = R·(V − 29.8 ŷ_GSM km/s) (exact).
  - `*_swi_norm` = R·`*_gsm_norm`, then re-normalized between the mean Shue98 / Jelinek2012
    boundaries at the new angles and clipped to [0, 1] (notebook cell 23). Direction is
    exact on all rows; radius differs on ~9 % of rows, all near a boundary. This is
    intended; PGSM uses `*_swi_norm` as served.
  - `*_swi` columns are null unless `Norma_pos` and `SW_pairing` are both true.
- Magnetosphere `tilt` (radians) = 23.4°·cos(2π(doy − 172)/365.25) + 11.2°·cos(2π(UT − 16.72)/24),
  exact to 1e-14° on 38k rows (THA, C1, MMS).
- Eq 2.17 (magnetosheath doubling symmetry) is internally inconsistent with eq 2.18 and the
  text as printed. Out of scope here until B. Michotte de Welle clarifies (§9).

## 3. Conventions

- Angles in the PGSM API are in degrees.
- IMF clock angle θ_cl = atan2(By, Bz): 0° = northward, 90° = +Y. Same convention as
  mango_explorer (`atlas/frames.py`).
- IMF cone angle = acos(Bx_imf/|B_imf|) in [0°, 180°], computed from the served GSM IMF
  columns: 0° = IMF pointing sunward (+X_GSM), 180° = earthward.
  Documented deviation: after SWI the samples are organized around −V_sw, a few degrees
  from X_GSM (aberration); the cone is still measured from X_GSM.
- Folded cone f = acos(|Bx_imf|/|B_imf|) in [0°, 90°]: the cone of the sample once in SWI
  (Bx > 0).

## 4. User API

```python
r = mango.get_data("magnetosheath", frame="pgsm", cone=[80, 100], clock=180, ...)
m = mango.get_data("magnetosphere", frame="pgsm", tilt=[10, 15], ...)
n = mango.count("magnetosheath", frame="pgsm", cone=[80, 100])
```

- `frame="pgsm"` is explicit. PGSM is never the default.
- Magnetosheath: `cone=[a, b]` and `clock=θ` are required. Magnetosphere: `tilt=[t1, t2]`
  is required. No defaults.
- All usual arguments still apply and act before the transform: `spacecraft`,
  `start`/`stop`, `columns`, range filters (e.g. `pd_sw_max=2`), `cache`.
- `frame="pgsm"` implies `normalized_only=True` (both regions) and `sw_paired_only=True`
  (magnetosheath).
- The columns needed by the transform are fetched even if not listed in `columns`, and
  dropped from the output unless the user asked for them.
- Same parameters on the region objects: `mango.magnetosheath.get_data(frame="pgsm", ...)`
  (generated signatures regenerated by `_codegen.py`).
- `count(..., frame="pgsm", ...)` returns the exact number of output rows (doubled rows
  counted twice); see §6.

Errors (subclass of `MangoError`, raised before any download):

- `frame="pgsm"` on `solar_wind`; an unknown `frame` value.
- `cone`/`clock` on the magnetosphere, `tilt` on the magnetosheath.
- A missing required parameter, or `cone`/`clock`/`tilt` without `frame="pgsm"`.
- Out-of-range values: cone not in [0, 180], clock not in [−360, 360], tilt not in [−35, 35],
  or a range with min > max.

## 5. Transform

New module `src/space_mango/pgsm.py`: pure polars functions, no network, no I/O.

### 5.1 Magnetosheath

Input rows: `Norma_pos` and `SW_pairing` true. Let f be the folded cone and
o = sgn(Bx_imf) the original sign (same fallbacks as SWI).

1. Selection by `cone=[a, b]`. For each row, two candidates:
   - s = +1, output cone f: kept if a ≤ f ≤ b;
   - s = −1, output cone 180° − f: kept if a ≤ 180° − f ≤ b.
   A row can give 0, 1 or 2 output rows (2 only if the range contains both f and 180° − f).
   `mirrored` = (s ≠ o): the output row is a mirror image of the measurement rather than
   the measurement itself. `bx_sign` = s.
2. Rotation to the target clock (eqs 2.19–2.20), Δ = θ_cl − 90°:
   - Positions, from `X/Y/Z_swi_norm`: X' = X; ρ = √(Y² + Z²), α = atan2(s·Y, Z);
     Y' = ρ sin(α + Δ), Z' = ρ cos(α + Δ) → `X/Y/Z_pgsm_norm`.
   - Magnetic field, from `B*_swi`: Bx' = s·Bx; ρ_B = √(By² + Bz²), β = atan2(By, s·Bz);
     By' = ρ_B sin(β + Δ), Bz' = ρ_B cos(β + Δ) → `B*_pgsm` (eq 2.20; axial vector).
   - Velocity, from `V*_swi`: treated as a polar vector like positions: Vx' = Vx;
     α_V = atan2(s·Vy, Vz); rotated by Δ → `V*_pgsm`. (Aberration-corrected, as served.)
   - Scalars unchanged.
3. Check built into the tests: the IMF in SWI, s·R·B_imf, maps to clock θ_cl, cone f
   (s = +1) or 180° − f (s = −1).

### 5.2 Magnetosphere

Input rows: `Norma_pos` true. ψ = `tilt` in degrees.

1. Originals with ψ in [t1, t2]: `mirrored` = false; PGSM columns equal the GSM ones.
2. Mirrored copies of rows with −ψ in [t1, t2] (eqs 2.14–2.16): `mirrored` = true;
   - positions (X, −Y, −Z) from `*_gsm_norm` → `X/Y/Z_pgsm_norm`;
   - magnetic field (−Bx, By, Bz) → `B*_pgsm`;
   - velocity (Vx, −Vy, −Vz) → `V*_pgsm` (rotation by π about X; B → −B does not touch V);
   - `tilt_pgsm` = −ψ (originals: ψ), in degrees.
   A row with both ψ and −ψ in range appears twice (only if the range contains 0).

### 5.3 Output

- All requested columns, as measured (originals of mirrored rows too: provenance).
- `X/Y/Z_pgsm_norm`, `Bx/By/Bz_pgsm`, `Vx/Vy/Vz_pgsm`, `mirrored`;
  `bx_sign` (magnetosheath); `tilt_pgsm` (magnetosphere).
- No raw (non-normalized) PGSM positions; no PGSM IMF/solar-wind vectors.
- `MangoResult.metadata` records frame, parameters, and the thesis reference.

## 6. Where things run

- Client: the transform always runs locally, on the cached monthly per-column fragments
  (default) or on rows fetched from the server (`cache=False` or `limit`). Changing
  `clock` reuses the cache.
- Server prefilter, to keep downloads small on the non-cache path: magnetosphere
  `tilt` in ±max(|t1|, |t2|) (radians); magnetosheath `normalized_only`, `sw_paired_only`.
- `count(frame="pgsm", ...)`: the selection expressions (cone candidates, tilt candidates)
  live in `pgsm.py` and are used by `filtering.py`, so the cache path and the server count
  the same rows. The server `/count` endpoint accepts `frame`, `cone_min`, `cone_max`,
  `tilt_min`/`tilt_max` with `frame=pgsm`. This is the only server change.
- Not in this version: server-side PGSM on `/data`, CORS.
- Compatibility: `get_data(frame="pgsm")` works against a 0.2 server. `count(frame="pgsm")`
  needs the new server; against an older one the client raises `ServerError` with an
  upgrade hint. Release order as for 0.2: deploy server, then publish client.

## 8. Tests (written first)

- Geometry: the transformed IMF lands at the target clock and cone; clock = 90°, s = +1
  reproduces the SWI columns; norms preserved; s = −1 equals the Y mirror of s = +1.
- Magnetosphere: the mirror applied twice is the identity; an analytic tilted dipole at ψ,
  transformed, equals the dipole at −ψ (small-scale version of thesis Fig 2.24).
- Selection: cone ranges below, above and across 90°; tilt ranges with and without 0;
  `mirrored`/`bx_sign` values; counts from `count()` equal output row counts (cache and
  server paths).
- API errors listed in §4.
- Integration through the in-process FastAPI fixture; one check on the real docs sample
  (magnetosheath vectors equal served SWI at clock 90°, s = +1).
